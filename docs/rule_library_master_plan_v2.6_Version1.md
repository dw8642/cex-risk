# 风控规则库正式版（V2.6 融合版）

## 0. 文档说明

### 0.1 文档目标

本文档用于在《CEX风控系统全面方案（V2.6 修订版）》基础上，正式形成**统一风控规则库**，并吸收：

- `docs/風險控制規則.md` 中的交易员原始规则；
- `docs/[3月24日]Risk梳理.md` 中的规则梳理、重复项分析和优先级排期。

本文档重点解决以下问题：

1. 将交易员规则正式收编进最新风控系统框架；
2. 统一规则编号、分层结构与命名规范；
3. 区分平台统一规则、执行基础规则、策略专属规则；
4. 补充现有 V2.6 中未显式建档、但业务强依赖的规则；
5. 输出统一的优先级体系，指导老板评审、交易员确认、产品设计和研发排期。

---

- 交易负责人 / 交易员
- 风控负责人

- 后端 / 数据 / 前端研发

## 1. 规则库建设原则

### 1.1 统一框架不推翻
`risk_control_plan_v2.6.md` 已经提供了完整的五层方法论和主风险框架，因此本次规则库建设不推翻原框架，而是在其基础上补足规则层。([]())

---

### 1.2 交易员规则不直接照搬，需标准化收编
`docs/風險控制規則.md` 提供的是交易员和策略侧视角的原始规则来源，规则价值很高，但存在：

- 命名体系不统一
- 部分规则表达不严谨
- 部分规则更像策略引擎守卫，不完全属于平台风控
- 大多数规则缺少恢复条件、冷却、去重和上下文说明

因此，这些规则应经过统一抽象后并入正式规则库，而不是原样照搬。([]())

---

### 1.3 历史梳理结果要继承
`docs/[3月24日]Risk梳理.md` 已经完成了三件有价值的事情：

1. 把交易团队关注点按 P0 / P1 / P2 做了优先级拆分；
2. 提示了若干规则重合项，如 `ORD-001` 与 `BASE-002`；
3. 明确指出了部分规则依赖交易引擎配合，风控平台本身做不到。([]())

因此，本次正式版规则库必须继承这些判断，而不是重新发明一套脱离业务现实的排期。

## 2. 统一规则库分层结构

为兼容 V2.6 主框架与交易员规则来源，正式采用**三级规则库结构**。

---

## 2.1 一级：平台统一主规则库

用于覆盖所有账户、策略、交易所和项目的统一风控规则。

### 编号前缀
- `P`：权限类
- `B`：行为类
- `S`：系统类
- `M`：市场类
- `C`：平台合规类
- `E`：敞口类
- `L`：清算与生存类

### 作用
- 对应 V2.6 的主事件中心
- 用于统一告警、统一统计、统一 dashboard
- 用于老板与风控视角的统一风险语言

---

## 2.2 二级：执行基础规则库

用于覆盖所有机器人 / 执行器都应遵守的基础执行约束。

### 编号前缀
- `BASE`

### 典型内容
- 时间窗口检查
- 单笔订单规模 / 支出范围检查
- 下单价格偏离限制
- 下单间隔与节奏检查
- 执行账户 / IP 分布异常检查

### 作用
- 将策略侧 guardrail 标准化
- 避免规则散落在策略代码中无法统一审计
- 便于平台风控与策略引擎协同治理

---

## 2.3 三级：策略专属规则库

用于覆盖不同策略类型特有的执行风险。

### 编号前缀
- `ARB`：套利策略
- `LIQ`：流动性 / 网格策略
- `MAN`：市值管理 / 操纵执行策略
- `ACCDIS`：吸筹 / 出货策略

### 作用
- 显式体现策略差异
- 支持按策略类型展示、配置、预警和复盘
- 避免所有规则混在平台主规则库中失去可维护性

---

## 3. 编号与命名统一规范

### 3.1 主规则库继续沿用 V2.6 编号
例如：
- `E-001 净 Delta 过高`
- `S-016 API 频控耗尽风险`
- `C-004 账户被平台限制 / 降权风险`

### 3.2 交易员规则作为来源，不再作为最终编号
例如：

- `RISK-POS-001` → 收编为 `E-002A 单市场仓位集中风险`
- `RISK-BASE-003` → 收编为 `BASE-004 下单间隔与节奏检查`
- `RISK-MAN-A001` → 收编为 `MAN-001 理想价格偏离控制`

### 3.3 每条规则保留“来源规则编号”
建议字段：
- `source_rule_ids`

例如：
- `BASE-002` 的 `source_rule_ids = [RISK-ORD-001, RISK-BASE-002]`

这样既保持标准化，也保留业务来源。

## 7.2 规则字段补充原则

### 1. 系统动作不能只写“降级”
必须写清楚：
- 仅告警
- 降级
- 限制同向交易
- 暂停策略
- PAUSED
- 拒单
- 电话告警
- 人工审批

### 2. 恢复条件必须写清楚
必须回答：
- 自动恢复还是人工恢复
- 连续几个窗口恢复正常
- 恢复后模式如何回升

### 3. 上下文条件必须明确
至少支持：
- market_making mode
- hedge mode
- rebalance mode
- manual mode

### 4. 实现归属必须明确
可选值：
- `risk_platform`
- `strategy_engine`
- `shared`
