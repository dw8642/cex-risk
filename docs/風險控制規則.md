# 風險控制規則 (1)

# **系統風險控制規則政策（Rule Policy v1.0）**

本文件定義系統層級的風險控制規則政策（System Risk Rule Policy）。

所有規則僅用於風險監控與系統降級控制，不涉及交易方向或策略判斷。

實際門檻數值未載於本文件，均由風險控制參數資料庫（Policy Parameter Database）統一管理。

### **RISK-POS-001 — 單一市場倉位風險控制**

目的：避免單一市場倉位過度集中，導致方向性風險失控。

指標：position_usd = abs(position_qty) × mark_price

範圍：帳戶 + 市場

規則條件：position_usd > $PerMarketExposure

系統動作：系統運行模式降低一個等級（NORMAL → DEGRADED → RESTRICTED → PAUSED）

備註：不同模式使用不同的閾值，僅閾值不同，邏輯一致。

### **RISK-POS-002 — 全帳戶總風險敞口控制**

目的：防止多策略疊加導致整體風險失控。

指標：total_exposure_usd = Σ abs(position_usd)

範圍：帳戶 / 全球

規則條件：total_exposure_usd > $TotalExposureLimit

系統動作：系統運行模式降低一個等級。

### **RISK-POS-003 — 倉位變動速率限制**

目的：防止在短時間內快速吸籌或拋售。

指標：position_change_usd_1h, position_change_usd_24h

範圍：帳戶 + 市場

規則條件：position_change_usd_1h > $MaxPositionChangeHourly 或 position_change_usd_24h > $MaxPositionChangeDaily

系統動作：系統運行模式降低一個等級。

### **RISK-VOL-001 — 成交量節奏控制**

目的：避免短期內成交量異常放大。

指標：volume_usd_1h, volume_usd_24h

範圍：帳戶

規則條件：volume_usd_1h > $MaxVolumeHourly 或 volume_usd_24h > $MaxVolumeDaily

系統動作：降低參與度並降級系統模式。

### **RISK-VOL-002 — 單邊成交比例限制**

目的：避免長時間單邊吸籌或拋售。

指標：directional_ratio_1h, directional_ratio_24h

範圍：帳戶 + 市場

規則條件：directional_ratio > $MaxDirectionalRatio

系統動作：限制同向交易並降級系統模式。

### **RISK-ORD-001 — 單筆訂單規模限制**

目的：防止操作失誤或異常下單。

指標：order_qty, order_value_usd

範圍：帳戶 + 市場

規則條件：order_qty > $MaxOrderQty 或 order_value_usd > $MaxOrderValue

系統動作：拒絕訂單；若持續觸發，將系統降級。

### **RISK-ORD-002 — 訂單價格偏離限制**

目的：防止報價錯誤或過度激進的掛單。

指標：price_deviation

範圍：Market

規則條件：price_deviation > $MaxPriceDeviation

系統動作：拒絕訂單並可能降級系統模式。

### **RISK-ARB-001 — 套利未對沖風險控制**

目的：避免跨交易所套利單邊成交導致未對沖風險。

指標：unhedged_exposure_usd

範圍：策略 + 市場

規則條件：unhedged_exposure_usd > $MaxUnhedgedExposure

系統動作：限制套利策略並降級系統模式。

### **RISK-MKT-001 — 市場異常波動保護**

目的：當市場出現異常波動時自動收斂風險。

指標：price_jump_pct_1h, price_jump_pct_24h

範圍：Market

規則條件：price_jump_pct > $MaxPriceJump

系統動作：擴大掛單範圍、降低參與度並降級系統模式。

### **RISK-SYS-001 — 系統與資料異常保護**

目的：在交易所或系統不穩定時保護資金安全。

指標：api_error_rate_1h, api_error_rate_24h

範圍：帳戶 + 交易所

規則條件：api_error_rate > $MaxApiErrorRate

系統動作：降級系統模式，嚴重時進入 PAUSED 狀態。

# 系統風險控制規則政策_v1.1

# **RISK-BASE-001 — 時間範圍檢查**

- 目的：檢查 Bot 是否在 Config 設定的時間範圍內運行
- 指標：current_time, start_time, end_time
- 範圍：Strategy + Trades 資料表
- 規則條件：startTime > trades.exec_time > endTime
- 系統動作：系統更新為 PAUSED
- 備註：不同模式使用不同的閾值，僅閾值不同，邏輯一致。

# **RISK-BASE-002 — 最大交易支出控制**

- 目的：控制每筆訂單的最大/最小支出
- 指標：effectiveMinOrderSize, effectiveMaxOrderSize
- 範圍：Strategy + Trades 資料表
- 規則條件：effectiveMinOrderSize > trades.size > effectiveMaxOrderSize
- 系統動作：系統運行模式降低一個等級 ¹
- 備註：以 Base token 為單位。

# **RISK-BASE-003 — 下單間隔檢查**

- 目的：控制Bot下單間隔，避免被交易所偵測到高頻下單
- 指標：tickIntervalMs, randomDelayJitter
- 範圍：Strategy + Trades 資料表
- 規則條件：以獨立帳戶的下單歷史紀錄進行計算
    
    tick = tickIntervalMs * randomDelayJitter
    
    trades[n].execTime - trades[n-1].execTime > tick
    
    * 最終公式以[src/core/orchestrator.ts](http://orchestrator.ts/) 為準
    
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-BASE-004 — 訂單帳戶檢查**

- 目的：檢查下單所使用的帳戶，避免被交易所偵測到高頻下單
- 指標：tickIntervalMs, randomDelayJitter, maxDistributedAccounts
- 範圍：Strategy + Trades 資料表
- 規則條件：在 X 個 tick 間隔內，多筆訂單使用相同的 trades.executorIp 執行
    - N * tick * maxDistributedAccounts ≈ ∑trades.executorIp.length
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-MAN-A001 — 價格操縱風險控制**

- 目的：當當前市場價格超出理想價格時，暫停交易行為，直至價格回歸正常水平。
- 指標：exec_price, market_mid_price
- 範圍：操縱策略 + 交易表
- 規則條件：上漲時 trades.exec_price > ideal_price / 下跌時 trades.exec_price < ideal_price
- 系統動作：系統運行模式降低一個等級 ¹
- 備註：ideal_price 由 TWAP 演算法得出。可參考

[”active-bot/src/services/strategy/decision/manipulation.ts”](http://manipulation.ts/)

# **RISK-MAN-A002 — 訂單風險控制**

- 目的：減少訂單過度集中，避免製造市場假象
- 指標：reverseTradeProbability
- 範圍：Manipulation Strategy + Trades 資料表
- 規則條件：在 X 個時間間隔內，多筆訂單朝同一方向進行
    - ∑trades.side[“buy”] / ∑trades.side[“sell”] > reverseTradeProbability
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-LIQ-P001 — 網格控制 1**

- 目的：控制訂單位置，避免過於接近中間價
- 指標：midPrice, order.side, order.execPrice
- 範圍：流動性策略 + 交易表
- 規則條件：檢查限價單價格是否跨越中價
    
    買單：order.execPrice > midPrice
    
    賣出：order.execPrice < midPrice
    
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-LIQ-P002 — 網格控制 2**

- 目的：控制訂單位置，避免偏離設定值過遠
- 參數：maxGridLevels, minSpreadFromMidPct, orderPriceTolerancePct, midSpreadBetweenGridsPct
- 範圍：Liquidity Strategy + Trades 表格
- 規則條件：
    
    交易的 gridLevels 不會超過 maxGridLevels
    
    當前價格與第一筆掛單的價差不得超過 minSpreadFromMidPct
    
    僅當計算出的最新價差超過 orderPriceTolerancePct 時才會取消
    
    每筆訂單之間的點差以midSpreadBetweenGridsPct為基準
    
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-LIQ-P003 — 最大訂單量**

- 目的：控制每 tick 訂單的最大支出
- 指標：maxCapitalAllocationPct, currentInventory.baseTotal, trade.limitOrderPlaced
- 範圍：Liquidity Strategy + Trades 資料表
- 規則條件：
    
    ∑ trade.limitOrderPlaced.size <= maxCapitalAllocationPct * currentInventory.baseTotal
    
- 系統動作：系統運行模式降低一個等級 ¹

# **RISK-ACC/DIS-001 — 交易總額上限控制**

- 目的：檢查機器人交易總量
- 指標：totalTradingAmount, totalQuantity
- 範圍：Strategy + Trades 資料表
- 規則條件：totalQuantity > totalTradingAmount
- 系統動作：系統更新為 PAUSED

# **RISK-ACC/DIS-002 — 交易價格控制**

- 目的：檢查Bot是否在指定價格範圍內完成訂單
- 指標：priceLimit, exec_price
- 範圍：Strategy + Trades 資料表
- 規則條件：exec_price > priceLimit
- 系統動作：系統更新為 DEGRADED

**RISK-CroArb-001 — 訂單損益**

- 目的：訂單損益
- 指標：minSpreadBps, feeRateBps, midPrice, (bid/ask)[0]
- 範圍：策略
- 規則條件：
    
    buyPrice = Ask * (1+feeRateBps)
    
    sellPrice = bid * (1+feeRateBps)
    
    (sellPrice - buyPrice) / midPrice >  minSpreadBps
    

參考： “apps/active-bot/src/services/strategy/decision/cross-exchange-arb.ts”

- 系統狀態：系統更新 DEGRADED

備註：

¹ 系統模式將依序降級（NORMAL→aEGRADED→RESTRICTED→PAUSED）
